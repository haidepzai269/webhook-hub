## 1. Đúng tiền — `applyPayment` (`apps/shop/src/payment.ts:17-24`)

Code mới: trạng thái ∉ {PENDING, UNDERPAID, EXPIRED} thì giữ nguyên (PAID → `EXTRA_PAYMENT`, khác → `LATE_PAYMENT`). Ngược lại `late = status≠UNDERPAID && min(paidAt, now) − createdAt > TTL`; `full = paidAmount+amount ≥ amount đơn`; `status = full ? PAID : late ? EXPIRED : UNDERPAID`.

| Tình huống | Kết quả | Đánh giá |
|---|---|---|
| PENDING đúng hạn · đủ / dư | PAID / `PAID` | ✓ |
| PENDING đúng hạn · thiếu | UNDERPAID | ✓ |
| PENDING quá hạn (cron chưa chạy) · đủ | PAID / `LATE_PAID` | ✓ (test) |
| PENDING quá hạn · thiếu | EXPIRED / `LATE_PAYMENT` (hết hạn lười) | ✓ (test) |
| EXPIRED · paidAt đúng hạn (cold start, M-1) · đủ / thiếu | PAID / UNDERPAID, như trước | ✓ (test M-1 cũ còn xanh) |
| EXPIRED · trễ · đủ / dư | PAID / `LATE_PAID` | ✓ |
| EXPIRED · trễ · thiếu → nạp thêm đủ | EXPIRED → PAID, giao hoán theo cả hai thứ tự | ✓ (test `run([100k,38k])` và `run([38k,100k])`) |
| UNDERPAID (kể cả quá hạn) | không bao giờ "trễ": đủ → PAID, thiếu → UNDERPAID | ✓ |
| PAID nhận thêm | giữ PAID, cộng `paidAmount`, `EXTRA_PAYMENT` | ✓ |
| CANCELLED | giữ CANCELLED, cộng `paidAmount`, `LATE_PAYMENT` | ✓ (test mới) |
| OTHER_CHANNEL | `main.ts:140` return **trước** khi insert event và trước `applyPayment` → không cộng | ✓ không đổi |
| Trùng sự kiện | `processedHubEvent.findUnique` trong tx sau `FOR UPDATE` → `DUPLICATE`; chạy song song thì P2002 → `DUPLICATE` | ✓ không đổi |
| Khoá | `SELECT … FOR UPDATE` + optimistic `version` (`main.ts:134,144`) giữ nguyên; insert event và `paidAmount` cùng commit | ✓ |
| `paidAt` M-1 (ADR-144) | vẫn `min(paidAt, now)`; paidAt ở tương lai bị chặn | ✓ (test) |

**Nhận xét quan trọng:** sau ADR-154, mọi tổng tích luỹ ≥ giá đơn đều ra PAID, trừ CANCELLED. Vì vậy, nếu `paidAt` lệch (ví dụ timezone của SePay), hậu quả chỉ là đổi nhãn UNDERPAID ↔ EXPIRED cho khoản *thiếu*, không đổi kết quả tiền. Đường tiền giờ an toàn hơn trước.

**Reconcile:** `lateMoneyOrders = count(EXPIRED ∧ paidAmount > 0)` (`main.ts:185`) khớp với ngữ nghĩa mới: chỉ còn đơn trễ mà thiếu, cộng thêm các dòng EXPIRED *cũ* (trước ADR-154) đã đủ tiền nhưng chưa được nâng lên PAID (xem L-3). `expireStaleOrders` chỉ đụng PENDING, không ảnh hưởng LATE_PAID.

**Log:** `LATE_PAID` đi nhánh `logger.info` ✓.
